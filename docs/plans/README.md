# Plans

Multi-phase work, written so a stranger can resume it from the plan alone.
Plans execute decisions already made; they cite ADRs and research, never
re-litigate them.

## Conventions

- One directory per plan: `<YYYY-MM-DD>-<slug>/`.
- `README.md` per plan: an H1 goal (phrased as an outcome), a
  `- **Status:**` line for the plan as a whole, scope and non-goals, the phase
  status table, critical files, top risks, links to the ADRs and research it
  implements. The H1 and the status line feed the index. **Keep relative links
  out of the status line**: it is copied verbatim into `docs/plans/README.md`,
  one directory up, where a `../` link resolves somewhere else and
  `make docs-check` fails.
- `phase-NN-slug.md` per phase, each with **Goal**, **Tasks** (checkboxes),
  **Verification** (exact commands, `make check` at minimum), **Artifacts**
  (files that must exist when done), **Progress log** (dated appends only).
- A phase is one PR-sized, independently verifiable slice. Order by dependency,
  then by risk, so the riskiest assumptions surface first. Three to eight
  phases; more usually means two plans.
- **Status table, checkboxes, and progress logs update as-you-go**, in the same
  PR as the change. Append, never rewrite.
- Statuses: 🔵 Not started, 🟡 In progress, 🟢 Completed, ⏸ Deferred.
- Gates before a phase goes 🟢: `make check` green, verification commands run
  and output confirmed, artifacts exist. Can't run the check? The phase stays
  🟡 and the progress log says why.
- **Staleness is enforced.** `make docs-check` fails when a 🟡 In progress plan
  has no dated entry newer than 60 days. Mark it ⏸ Deferred, or delete it. An
  abandoned plan that still looks live is worse than no plan, because the next
  reader trusts it.
- Any mid-plan fork between real alternatives gets an ADR before proceeding.
- Scope changes get written in as a new phase or an amended goal. Renumbering
  is forbidden; new work gets new numbers.
- Write and work it with the `/plan` skill.
